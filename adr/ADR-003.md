# ADR-003 — ORM / capa de acceso a datos

- **Estado:** Aceptado  *(ratificado por el propietario, 2026-07-27)*
- **Fecha:** 2026-07-27
- **Decisores:** CTO (propuesta) · Propietario (ratifica)
- **Fase:** 0 (Investigación)

## Contexto

La base de datos es **PostgreSQL** (ver [`../docs/01_TECH_STACK.md`](../docs/01_TECH_STACK.md)).
Necesitamos una capa de acceso con: **migraciones robustas** (el esquema del dominio
evolucionará mucho), buena **DX** (dev en solitario + IA), seguridad de tipos, y encaje con
**NestJS** (ADR-002). Despliegue en servidor persistente (no edge).

## Opciones consideradas

### Opción A — Prisma (v7)
- **Ventajas:** **migraciones best-in-class** (`prisma migrate` avisa de cambios destructivos,
  guía el flujo); DX excelente; type-safety; schema declarativo claro; muchísima
  documentación/patrones (bueno con IA). **Prisma 7 (nov-2025)** eliminó el motor Rust
  (WASM/TS): bundle 14 MB → **1,6 MB** y ~3× más rápido → desaparece el histórico "pero".
- **Inconvenientes:** DSL propio (`.prisma`); en consultas muy complejas se recurre a SQL
  crudo (soportado).

### Opción B — Drizzle
- **Ventajas:** SQL-first, muy ligero, máximo control y rendimiento; ideal para edge.
- **Inconvenientes:** migraciones/DX aún por detrás de Prisma; `push` sin migraciones puede
  causar *schema drift* si no se cuida; ecosistema más joven. Su ventaja (edge/perf extremo)
  no es crítica para nosotros.

### Opción C — TypeORM
- **Ventajas:** maduro, decoradores que encajan con Nest.
- **Inconvenientes:** más fricción/rarezas; DX y migraciones peores que Prisma.

## Decisión

**Prisma 7 (Opción A).** Para un esquema de dominio que **cambiará mucho** y un dev en
solitario, la **madurez de migraciones + la DX** de Prisma son la mayor palanca de
productividad y seguridad. Con Prisma 7 desaparece el antiguo inconveniente del binario Rust.
El schema de Prisma vive en **`apps/api`** (propiedad del backend); el cliente Prisma **no
sale del servidor**. Para consultas muy calientes/complejas usaremos SQL crudo puntual.

## Consecuencias

- **Positivas:** migraciones versionadas y seguras; iteración rápida del modelo; tipos
  compartibles; integración conocida con NestJS.
- **Negativas / coste asumido:** dependencia del DSL de Prisma; algún caso extremo requerirá
  SQL manual.
- **Impacto:** el modelo de dominio (Sprint 1, ADR-006) se materializa como schema Prisma +
  migraciones. Los **tipos del dominio** compartidos con el frontend viven en
  `packages/domain` (ADR-004), no el cliente Prisma.

## Notas / seguimiento

- Vigilar rendimiento en las consultas de puntuación/jornada; medir antes de optimizar.
